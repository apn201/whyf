# The corpus

Two corpora. One ships, one does not.

## What ships: `synthetic.tsv`

223 questions written here, generated by `tools/gen_synthetic.py` from the
concept catalog. Every concept has at least one row, and all the question forms
are represented - statement, direct question, four-rung maturity ladder, plus
the admin, disclosure and attestation rows that exercise the classifier's
non-control classes.

It is deliberately blander than the real thing. Real questionnaires are worse
written than anything we would invent. It exists so that:

- the repo runs from a clean checkout, which the submission rules require;
- a judge can paste something in and watch the tiers fire;
- the tests have a corpus even with no private data present.

The underlying controls are industry-standard. Nobody owns "do admin accounts
need a second factor". What is owned is a particular set of questions in a
particular wording and arrangement, and none of that is reproduced - the
generator was written against concept ids, not against the source text.

## What does not ship: `../private/`

Gitignored. Three real questionnaires and everything derived from them.

| id | rows | what it is |
|---|---|---|
| `q1` | 116 | a supplier questionnaire, binary statements, heavy on industrial control systems |
| `q2` | 142 | two vendor questionnaires, mostly four-rung maturity ladders |
| `q3` | 106 | NIST CSF 2.0 subcategories from a trade-federation checklist workbook |
| | **364** | |

Also there: `crosswalk.tsv` (a compiled mapping from CSF subcategories to NIS2,
ISO and IEC identifiers), `nist-csf-relevance.tsv` (the workbook's IT/OT
relevance ratings), `benchmarks.yaml` (a peer maturity benchmark), `rules.py`
(the regexes that map real rows to concepts - they are fragments of somebody
else's wording, so they cannot ship either), and `context/*.md`, one writing
aid per concept.

### Why

- **The questionnaire wording is the asker's.** Reproducing 116 rows of a
  customer's security questionnaire is a substantial reproduction, and it may
  identify the customer.
- **The instrument behind `q2` is a commercial product.** A completed
  assessment against it turned up as a fifth file, and its scoring page names
  it: 9 domains, 35 control areas, 110 questions. Republishing the question set
  would be republishing somebody's product.
- **The crosswalk is compiled work.** The individual identifiers are facts, but
  a 190-row mapping represents real effort by whoever built it, and in the EU
  database right protects that separately from copyright.
- **The assessment identifies its subject.** Sector, headquarters, a
  turnover-relative loss estimate, the assessment date, and free-text fields in
  which staff describe their own weaknesses. None of it is extracted and none of
  it may be.

### The benchmark, and why its numbers stay put

The assessment carried a peer column: average maturity per control area across a
large peer pool, on the same 1-4 scale as the corpus ladders. That is genuinely
useful for deciding which rung is enough.

It is also **one segment's** benchmark. The assessed company is an industrial
manufacturer, the report shows an industry average and a higher global average,
and it does not say which pool the per-area column comes from. Regulated sectors
score higher. A bank is not the peer group of a packaging plant.

So the numbers stay in `private/benchmarks.yaml` and reach cards only through
`private/context/*.md` while they are being written. What ships is the sentence
the writer produces in `why_not_4` - a judgement, in their own words, scoped to
the sector it applies to.

## What stayed public

`../knowledge/frameworks/nist-csf.yaml` carries all 106 CSF 2.0 subcategories
with their text. CSF is a US government publication in the public domain and can
be quoted freely. The relevance ratings that came with the workbook are the
compiler's editorial judgement, not part of CSF, and those went private.

The other framework files hold identifiers only - control numbers are facts, the
standards themselves are copyrighted.

## Running it

Clean checkout, no private data:

```bash
python tools/check.py
```

Everything passes. Coverage is reported against the synthetic corpus and says so.

With `private/` present, coverage is reported against the 364 real rows instead,
because covering questions we wrote ourselves proves nothing. That is the number
worth quoting in the writeup; the synthetic number is what a judge can reproduce.

Regenerating the public corpus:

```bash
python tools/gen_synthetic.py
```

Regenerating the private one, which needs the source files:

```bash
python tools/parse_q2.py && python tools/parse_annex.py
```

## Before publishing

```bash
python tools/check_publishable.py
```

Scans every file that ships for six-word runs taken from the real
questionnaires, for identifiers from the assessment report, and for a
`.gitignore` that has stopped covering `private/`. It runs inside `python tools/check.py`
and it is not decorative - it caught fifteen real leaks the first time it ran,
including two in cards, two in the pattern library and one phrase that had
drifted into the synthetic corpus.

The failure mode it exists for is not committing `private/` by accident. It is
pasting one real question into a card while writing.

## Adding another questionnaire

1. Drop it in `private/` and write a parser emitting `id, section, form,
   question, options`.
2. Register it in `load_rows()` in `tools/corpus_map.py`.
3. Run `python tools/corpus_map.py`. It reports duplicates against everything
   already loaded, using the same hash as the tier-0 cache, and lists every row
   no rule claimed.
4. Add rules to `private/rules.py` until nothing is unmapped, then
   `python tools/gen_skeletons.py`.
5. If the new source introduces a concept, add a synthetic row for it so a clean
   checkout can still demonstrate it. A test enforces this.

Step 3 is not optional. Of the five files collected so far, one was a
byte-identical copy of another and one was not a questionnaire at all.
